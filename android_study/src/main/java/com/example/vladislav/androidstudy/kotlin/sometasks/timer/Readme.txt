Таймер на MVVM

Реализация таймера с отсчетом времени, построенная на архитектурном паттерне MVVM. Разработана для использования в Android-приложениях с Jetpack Compose и корутинами.

Архитектура
    Решение следует принципам MVVM с разделением ответственности:
    Model описывает бизнес-логику и состояния таймера через sealed class
    View отвечает за отображение интерфейса и подписывается на изменения данных
    ViewModel управляет состоянием, обрабатывает действия пользователя и предоставляет данные для отображения

Состояния таймера
    Таймер проходит через пять состояний:
    Initial - начальное состояние, время равно нулю
    Started - таймер запущен и ведет отсчет
    Paused - таймер приостановлен
    Resumed - таймер возобновлен после паузы
    Stopped - таймер остановлен и сброшен
    Переходы: Initial -> Started -> Paused -> Resumed -> Paused ... и из любого состояния в Stopped.

Реализация
    Основной механизм
    Таймер построен на корутинах с использованием viewModelScope, что обеспечивает автоматическую отмену при уничтожении ViewModel. Цикл обновляет значение каждые 16 миллисекунд для обеспечения 60 кадров в секунду и плавного отображения.
    Для измерения времени используется монотонный источник, защищающий от изменений системного времени.
    Управление паузой
    Пауза реализована через Mutex. При паузе блокировка активируется и корутина приостанавливается. При возобновлении блокировка снимается и работа продолжается.
    Время паузы запоминается и вычитается при возобновлении, чтобы оно не учитывалось в общем времени.

    Работа с потоками
    Все операции выполняются на главном потоке по следующим причинам:
    delay() не блокирует поток, а лишь приостанавливает корутину
    Mutex с пустым блоком не выполняет тяжелых операций
    Измерение времени - мгновенная операция
    Обновление состояния должно происходить на главном потоке для немедленного обновления UI
    Отсутствие переключения контекста устраняет оверхед и задержки
    Переключение на фоновый поток не дает преимуществ, так как delay все равно не блокирует поток, но добавляет накладные расходы на переключение контекста.

    Управление состоянием
    Для управления состоянием используются StateFlow:
    Поток текущего времени обновляется каждые 16 мс
    Поток текста кнопки изменяется в зависимости от состояния
    Внутренний поток управляет логикой переходов
    StateFlow гарантирует, что UI всегда получает актуальные данные и автоматически обновляется при изменениях.

    Жизненный цикл
    Таймер привязан к жизненному циклу ViewModel через viewModelScope. При создании ViewModel автоматически запускается наблюдение за состояниями. При уничтожении все корутины отменяются, а ресурсы очищаются.
    Преимущества
    Чистая архитектура с разделением ответственности
    Реактивность через StateFlow

    Потокобезопасность через Mutex
    Точность измерений через монотонный источник времени
    Автоматическое управление жизненным циклом
    Отсутствие лишних переключений контекста
    Простота отладки благодаря выполнению на главном потоке

Ограничения
Реализация предназначена для работы в UI-потоке и не подходит для выполнения тяжелых вычислений. При необходимости добавления ресурсоемких операций потребуется выносить их в фоновые потоки.
